# Layout

Layout turns product priority into reading order, grouping, rhythm, and usable space.

## The Squint Test

Blur the screen. Can you still read primary, secondary, tertiary in order?
If not, hierarchy is flat.

## Rhythm

- Tight groups, generous separation
- More space above a heading than below
- One spacing scale, 4-based or 8-based
- Vary density: a dense section earns a quiet one
- Same spacing everywhere = no rhythm

## Grid

- 12-column is a starting point, not a rule
- Asymmetry is intentional, not accidental
- Break the grid once, deliberately
- Optical corrections come after mathematical alignment

## Cards

Cards contain discrete, equivalent items.
If items are not equivalent, do not card them.
If items are not discrete, do not card them.

Never: nested cards.
Never: every section is a card.
Never: cards to compensate for weak proximity.

## Reading Order

DOM order = visual order = focus order.
Test with keyboard Tab.
If Tab order surprises you, the layout is wrong.

## Responsive

- Responsive behavior is structural, not just fluid type
- Collapse sidebars, reflow tables, stack columns
- Test at 320px, 768px, 1440px minimum
- Touch targets 44x44px minimum

## Density

Match density to use frequency:

- High-frequency (dashboards, lists): compact
- Low-frequency (settings, forms): generous
- Reading (docs, articles): measure-first

## Depth

Use depth only when it clarifies state or hierarchy.
Otherwise, borders and background shifts do the job.
